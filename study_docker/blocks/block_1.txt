БЛОК 1 — Docker с нуля: образ, контейнер, порт и три места, где всё ломается

Сессия 1, нулевой старт. Шесть вопросов, 12 баллов, 25 минут. Урок и игра уже позади:
здесь проверка, а не обучение. «Не знаю» — нормальный ответ, он ничего не портит.

=== ЧАСТЬ 1. ПО УРОКУ (10 минут) ===

1. Ты собрал образ командой
      docker build -t app .
   и запустил из него контейнер. Потом сделал
      docker rm -f 7c1a2b
   Ответь тремя пунктами: что такое образ, что такое контейнер, что осталось на диске
   после удаления контейнера и почему.

2. Приложение запускается так:
      docker run -p 8000:5000 app
   Внутри контейнера сервер слушает порт 5000.
   а) какой адрес открывать в браузере на своём компьютере;
   б) почему не localhost:5000, хотя приложение слушает именно 5000;
   в) что изменится, если запустить без -p.

3. Вот Dockerfile, он работает, но собирается заново три минуты после каждой правки
   одной строки кода:
      FROM python:3.12-slim
      WORKDIR /app
      COPY . .
      RUN pip install -r requirements.txt
      CMD ["python", "app.py"]
   Что здесь стоит поменять местами и почему это убирает три минуты. Достаточно двух
   строк Dockerfile в правильном порядке и одной фразы про кэш.

=== ЧАСТЬ 2. ДВА НОВЫХ СЛУЧАЯ (15 минут) ===

4. Запустил
      docker run app
   и команда сразу вернула управление, а в списке работающих контейнеров пусто.
   Назови три разные причины, почему так бывает, и две команды, которыми ты узнаешь,
   какая из них твоя.

5. В Dockerfile написано
      CMD python app.py
   а в другом проекте —
      CMD ["python", "app.py"]
   Обе строки запускают приложение. Чем они отличаются и в каком случае Ctrl+C
   в терминале не остановит сервер, а контейнер придётся снимать через docker kill.

6. Приложение пишет данные в файл базы внутри контейнера:
      sqlite3.connect("/app/data/app.db")
   После
      docker rm -f app1
   и запуска новой копии базы нет — все записи пропали.
   Что происходит с файлами внутри контейнера при удалении, и какой флаг в docker run
   это лечит. Одной фразы «данные хранятся в контейнере» недостаточно: нужно ещё,
   какая часть пути на хосте и какая внутри.
