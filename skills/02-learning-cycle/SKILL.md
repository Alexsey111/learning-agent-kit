# Цикл сессий: блоки, ключи, возвраты

Одна сессия = один вход в компьютер, а не календарный день. Цикл держит состояние файлами,
поэтому он поднимается после паузы любой длины и не зависит от того, включён ли компьютер
между встречами.

## When to Use

- Диагностика пройдена, план тем есть, пора вести блоки.
- Пришло «проверяй ответы», «готово», «проверь, как я ответил» или просто путь к папке проекта.
- Нужно собрать следующий блок и не сломать очередь повторов.
- Не для: первичной диагностики (`direction-diagnostic`), уроков и приборов
  (`lessons-and-checks`).

## Файлы цикла

```
study/current.txt            блок текущей сессии — его показывает тренажёр
study/blocks/block_N.txt     архив блоков по номерам сессий
study/keys/block_N_key.txt   ключ, ученику не показывается
study/state.json             session, тема, очередь повторов, клетки, история
study/answers/               block_N_answers.txt / .json, block_N_draft.json
study/gaps/                  разборы: block_N_razbor.txt, diagnostic_report.txt
study/topic_plan.md          план тем
study/PROGRAM.md             итоговая программа (обновляется по ходу)
trainer/trainer.py, web/     локальный тренажёр, стандартная библиотека, без сети
start.cmd                    запуск тренажёра (Windows; в Linux/mac — python trainer.py)
```

Номер файла блока, ключа и ответов = номер сессии. Тренажёр берёт номер из `state.json`
в момент сохранения, поэтому **порядок один**: поднял сессию — сохранил копию state,
и только потом собрал новый блок. Иначе старое окно запишет ответы прошлого блока
в файл нового.

## Разметка блока

```
ЗАГОЛОВОК БЛОКА — тема и что проверяется
Сессия N: одна строка о составе (сколько возвратов, что нового).

=== ЧАСТЬ 1. ВОЗВРАТЫ (9 минут) ===

1. Сцена с числами и вопрос — на решение, с указанием, что именно назвать.

=== ЧАСТЬ 2. НОВОЕ (11 минут) ===

4. Сцена новой темы.
```

Правила разметки жёсткие (их читает парсер): первая строка — заголовок, вторая —
подзаголовок (ровно одна), секции `=== ... ===`, вопросы — строки `N. текст` от нулевой
колонки, продолжение — с отступом. Подзаголовок, начинающийся с цифры, парсер примет
за вопрос.

## Сборка блока

6–8 вопросов: 2–3 возврата + 3–5 новых внутри открытой темы. Число новых — по бюджету
времени (20–40 минут), а не по красоте.

- Возвраты ставить на те клетки, у которых подошёл срок (+3 или +10 сессий от провала).
- Новое — только внутри темы. Прыжки по полям дают нулевую глубину.
- Первый блок новой темы несёт 2–4 определения дословно (precision/recall, сплит, идемпотентность,
  порог). Без них вопрос неотвечаем, и ноль меряет словарь, а не понимание.
- Блок без нового материала — легальный формат: возвраты на новых числах плюс одна клетка,
  у которой носитель уже собран. В шапке писать «новых тем нет, числа другие».
- Возврат собирать сценой-контрапунктом: та же формула, другой вердикт. Блок, где у всех сцен
  один вывод, меряет заученную фразу.
- Теорию в блок не вставлять: она уходит в разбор после проверки.

Проверка блока до выдачи — парсером, не глазами:

```
python -c "import sys; sys.path.insert(0,'trainer'); from trainer import parse_block; \
d=parse_block(open('study/current.txt',encoding='utf-8').read()); print(d['title'], d['subtitle'], d['count'])"
```

Ожидание: заголовок, подзаголовок, ровно задуманное число вопросов.

## Приём результата

1. Сначала выяснить, ЧТО сохранилось: `block_N_answers.json/.txt` — кнопку «Готово»
   нажимали; `block_N_draft.json` — только автосохранение. Нет итогового файла → блок
   не сдан: считать охват по черновику и писать «сумма из N не считается».
2. Пустые строки — «не дошёл», а не «не смог»: страница отдаёт все ключи.
3. Ответы приходят файлом, не пересказом в чат. Если пришли текстом — записать их
   каноническими файлами с пометкой «перенесено, кнопка не нажималась» и только потом
   ставить балл.
4. Старый тренажёр после проверки закрыть (порт), иначе окно живо и может перезаписать
   файл нового блока.

## Оценка и разбор

Сначала охват и сумма, потом тип поломки по клетке. Неверное число называть с источником:
значение прошлой сцены, линейное отношение вместо квадрата, перепутанное окно агрегации.
Источник и есть тип поломки, по нему выбирается носитель.

Разборов не больше двух за сессию. Каждый разбор: 2–3 шага теории на числах его сцены,
«откуда взялось неверное число», что уцелело и сдвинулось. Файл `study/gaps/block_N_razbor.txt`
плюс та же теория в чате: файл один обучением не работает.

Форма разбора — `templates/razbor.template.txt`, семь разделов: что получилось, по вопросам
(ответил → что не так → как правильно), теория по клеткам, что сдвинулось, очередь повторов,
следующий блок, одна фраза ученику. Правила, без которых разбор бесполезен:

- на каждый провал — теория, а не оценка. Тип поломки берётся из ключа (не тот факт, факт без
  причины, причина без факта, подмена термина, перепутаны местами) и от него выбирается носитель;
- теория пишется на сцене блока: «образ app остался, потому что…», а не «образ — это…»;
- у каждой клетки есть шаг проверки: команда или действие, которым правило видно самому.
  Теория без шага проверки — это пересказ;
- «не знаю» — не провал и не ноль личности: клетка остаётся `open`, теория пишется полностью,
  носитель меняется (урок или прибор), возврат ставится по обычной очереди. Требовать ответа
  на вопрос, которого не объясняли, — ошибка ассистента, а не ученика;
- если клетка не сдвинулась два блока подряд, третий разбор того же устройства не пишется:
  меняется носитель, и это фиксируется в разборе явно;
- проверка усвоения — соседняя задача на той же клетке с другими числами или другим именем
  файла, а не вопрос «понял?».

## Очередь повторов

- Провал (0–1 балл) — возврат через 3 сессии и через 10.
- Половина клетки сдана (1.5) — возврат через 3, формулировка носителя меняется.
- Клетка закрыта (2 дважды подряд) — редкий повтор, раз в 8–10 сессий.
- Клетка не сдвинулась два блока подряд — третий разбор того же устройства не пишется:
  меняется носитель (текст → прибор → урок → контрапункт). Пересказ прежнего разбора
  меряет узнавание собственного текста.

В `state.json` у каждой клетки: `id`, `text` (что именно не так), `due_session`,
`repeat_session`, `note` (история: что ответил, какой балл, что дальше).

```json
{
  "track": "<направление>",

  "status": "block_issued",
  "current_topic": "metrics",

                    "due_session": 10, "repeat_session": 13, "note": "..."}],
  "gaps": [{"id": "g1", "session": 3, "text": "...", "file": "study/gaps/block_3_razbor.txt",

  "next_step": "сессия 12: start.cmd -> блок 12"

```

## Закрытие сессии

1. Следующий блок собран, `session` поднят, копия state сохранена.
2. Тренажёр закрыт, порт свободен.
3. `PROGRAM.md` обновлён одной строкой.
4. Снимок папки (git-коммит или архив): машина между сессиями выключена, непушенное
   считается потерянным. В закрывающем сообщении назвать, куда ушёл снимок.

## Pitfalls

- Собирать блок до подъёма сессии: ответы запишутся в прошлый файл.
- Проверять выдачу по HTML: разметка полей строится скриптом, в ответе сервера полей ноль
  и на здоровой странице. Число вопросов брать из парсера.
- Ставить блок в тот же вечер после разбора: меряется кратковременная память.
- Требовать в ключе то, чего не давал: перед записью требования проверить, был ли материал
  в разборах и уроках. Если нет — это первый проход, балл не снижается.
- Оставлять в `web/*.html` ссылки на прошлый номер блока: первая же ссылка уводит к сданному.
- Держать два номера в одном проекте (сессия и файл блока): через три сессии ключ ищется
  не там.

## Verification

- `study/current.txt` — блок ТЕКУЩЕЙ сессии, `state.json.session` равен его номеру;
- копия `state.json.bak_NN` существует;
- `parse_block` вернул ожидаемое число вопросов, ключ лежит отдельно и написан до ответов;
- по каждому провалу в ответе ученику есть теория на его числах, а не только ссылка на файл;
- в очереди повторов у каждого провала стоят due и repeat;
- тренажёр после проверки закрыт, порт свободен;
- снимок папки сделан и его имя названо.
