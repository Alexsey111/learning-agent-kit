БЛОК 1 — ключ (пример для принимающего агента)

Сцены проверены: срезы и алиасы — детерминированный Python, арифметики в сценах нет,
память и время названы качественно (без чисел, которые нельзя гарантировать на любой машине).

1. (2 балла) «a = [1, 2, 3, 4], b = [1, 2, 3, 4, 5]. b.append(4) меняет тот же объект,
   на который смотрит a, поэтому a тоже вырос. b = b + [5] создаёт НОВЫЙ список и
   перепривязывает имя b, a к нему отношения не имеет».
   1.5 — оба результата верны, причина «список изменяемый» без различения мутации
     и перепривязки.
   1 — верен только a (или только b): алиас не увиден.
   0 — «a = [1,2,3], b = [1,2,3,4,5]» как полный ответ; «?»; пусто.

2. (2 балла) «KeyError: 'user' — обращение по ключу требует его наличия. Переписать:
   data.get("user", {}).get("id") (или try/except KeyError). get возвращает None/дефолт
   вместо исключения».
   1.5 — «чтобы не падало» без имени исключения.
   1 — «так короче» / «удобнее».
   0 — «?», пусто.

3. (2 балла) «cde, fgh, hgfedcba, aceg».
   1.5 — три из четырёх.
   1 — два из четырёх.
   0 — «?», пусто, порядок перепутан целиком.

4. (2 балла) «Список строит все значения сразу и держит их в памяти; генератор выдаёт
   по одному и проходится один раз. Список — когда нужен повторный проход или индексация,
   генератор — один проход по огромному ряду, экономя память».
   1.5 — разница названа, «когда что» нет.
   1 — «генератор быстрее» без причины.
   0 — «?», пусто.

5. (2 балла) «Без индекса — полный скан всех 10 млн строк, время растёт линейно. Нужен
   индекс по email (B-tree): поиск по равенству спускается по дереву, а не читает таблицу.
   Индекс ускоряет поиск/сортировку по этой колонке, а не запросы вообще».
   1.5 — скан и индекс названы, причины нет.
   1 — «добавить индекс» без объяснения.
   0 — «?», пусто, «база сама разберётся».

6. (2 балла) «Между SELECT и UPDATE второй экземпляр успевает списать, проверка в коде
   не атомарна — гонка. Решение: проверить и списать одним запросом
   UPDATE accounts SET balance = balance - 100 WHERE id = 7 AND balance >= 100,
   смотреть rowcount; либо SELECT ... FOR UPDATE в транзакции. Свойство — атомарность».
   1.5 — гонка названа, решение «транзакция» без атомарной проверки в том же запросе.
   1 — «использовать транзакцию» без причины и без условия.
   0 — «?», пусто, «баланс не уйдёт в минус, потому что проверка есть».

Шкала: 0/1/1.5/2, сумма из 12. <6 — клетка открыта, носитель меняется (урок или прибор).
6–9 — возврат через 3 сессии. 9.5–12 — через 10.
